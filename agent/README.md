# agent

The voice agent server, built with the Claude Agent SDK (TypeScript, model `claude-sonnet-5-5`). It takes transcribed turns from `voice/`, drives the browser through Open Claude in Chrome and sends replies back to be spoken.

## Run

```bash
cd agent && npm install && npm start      # http://localhost:5050
```

Needs `ANTHROPIC_API_KEY` and `CARTESIA_API_KEY` in the repo-root `.env`, and Chrome running the Orbi extension (`CLEARCART_BROWSER=ext`) or the Open Claude in Chrome extension. Paying needs the Orbi extension and a card saved in its settings (Payment cards), or the Visa test card from `npm run add-test-card`.

## Files

- `server.ts`: static `voice/public` at `/`, `GET /cartesia-token` (POST `https://api.cartesia.ai/access-token`, `Cartesia-Version: 2026-08-14`, TTS and STT grants, returns `{ token, expires_in: 300 }`), `GET /healthz`, the settings page's `/memory` and `/cards`, WebSocket `/session`; requests must carry a local `Host` header, and WebSocket upgrades an `Origin` that is the Orbi extension or this server's own page (or none, for clients that are not browsers), so a web page cannot open `/session` and speak as the user.
- `hub.ts`: one voice session for every `/session` socket. The socket the user last talked into owns it (`interrupt` claims it; `user_text` does too, unless that socket lost the session since, then it gets `{ type: "standby", reason: "stale" }` and the words are dropped). Output goes to the owner only. On a change of owner the old one gets `{ type: "standby", reason: "moved" }`, a read-back or unlock question still waiting is declined (never confirmed) and the turn in progress is muted. The session ends with the last socket or when its agent stops.
- `session.ts`: one `query()` for that session with streamed user turns, the `request_checkout` and `pay_with_saved_card` tools, and the PreToolUse guard.
- `pay.ts`: the `pay_with_saved_card` logic. `money.ts`: amounts in cents with their currency, and a page's order total. `bridge.ts`: our own client for the extension's bridge socket.
- `cards.ts`: the saved cards for the settings page (`GET /cards`, `POST /cards`, `DELETE /cards/<id>`, `POST /cards/<id>/default`), for loopback peers with the Orbi extension's `Origin` only, with a JSON body limit and a rate limit. A list holds each card's id, nickname, brand and last 4, never its number, expiry or code. The vault itself is `vault/index.ts`; `add-test-card.ts` saves the Visa test card.
- `hostcheck.ts`: the `Host` header check (DNS rebinding defense).
- `unlock.ts`: the button lock's unlock gate. `ocic-lock.ts`: the button lock checks for the Open Claude in Chrome path. `origins.ts`: the browse mode, allowed and blocked origins, and `usableSite`, where paying may happen. `blocklist.ts`: the blocked sites check, imported from `extension/lib/blocklist.js`.
- `prompt.ts`: the system prompt.
- `local/`: the local model backend. `config.ts` parses and checks the provider settings (the URL must be on this computer), `openai.ts` is a minimal non-streaming chat-completions client (redirects refused; Ollama's own `/api/chat` when the server is Ollama, for its context window) plus the model list, and `query.ts` is the agent loop `Session.run()` uses instead of the SDK's `query()`. Every tool call there goes through the same gates in the same order: only `allowedTools` minus `disallowedTools` are offered and anything else is refused, then the same PreToolUse guard with the SDK's input shape (a deny is the result and the tool never runs; a hook that throws denies too), then the same tool definitions with their zod checks, then the same PostToolUse hooks, whose notes go to the model with the result. A turn stops after 25 model calls, on interrupt (the request in flight is aborted) or on an error, which is spoken in a few words ("I can't reach your local model at localhost:11434..."). Changing the provider setting makes the hub replace the session like a hand-off, once any payment under way has finished: no read-back, unlock question or unused yes carries over, while the card guard and a paused tab sweep do. A question whose tool call is cancelled (it timed out, or the agent stopped) stops waiting, so the user's next words are never its answer. `GET /local-models[?baseUrl=]` lists the endpoint's models for the settings page (`{ ok, connected, baseUrl, models: [{ id, tools? }], current }`, 502 when it is down), loopback peers with the extension's `Origin` only, like `/memory`.
- `memory.ts`: saved facts and the recent conversation, on this computer only. Facts are saved only by the `remember` tool, at once when the user's own last words asked to remember it and the fact is made of their words, otherwise after a spoken yes; `forget` works the same way and `recall` lists them. A filter refuses card numbers, security codes, passwords, government IDs, bank details, emails, long numbers and anything that reads like an instruction. The conversation keeps only the user's words and Orbi's spoken replies (never page text or the context block, long numbers removed) and is put in front of the next session's first turn as quoted data, so a restart picks up where it left off. Facts about shipping, addresses, paying or pressing buttons are refused too, at most one fact per spoken ask saves without a question, and a memory question is never asked while a checkout read-back or unlock question waits. In ext mode Memory is off until the extension says it is on. `GET /memory`, `DELETE /memory/<id>` and `DELETE /memory` serve the extension's settings page: loopback peers with the Orbi extension's `Origin` only.

## How the browser is wired

The extension's native host owns a unix socket (`$TMPDIR/open-claude-in-chrome-<uid>/bridge.sock`) and multiplexes any number of clients onto the one native-messaging link. A second server does not conflict with the one Claude Code runs: several were attached at once while this was built. Each session spawns its own `host/mcp-server.js` as the SDK's stdio MCP server (`mcp__browser__*`). Our own lock checks connect to the same socket directly from our process.

All clients share one "MCP" tab group in the browser, so a Claude Code session driving the browser at the same time sees the same tabs. Don't run both at once during the demo.

## Guardrails

- Built-in Claude Code tools are off (`tools: []`), and settings, CLAUDE.md files and user MCP servers are not loaded (`settingSources: []`, `strictMcpConfig`). `permissionMode: "dontAsk"` denies anything not in the allow list.
- Never available: `execute_code` (its sandbox could call every browser tool and get around the guard), `javascript_tool` (page script could press a locked button; our own lock checks still use it over our own client), `gif_creator`, `read_network_requests`, `debug`, `get_config` and `set_config`, uploads, shortcuts and the recording tools.
- `navigate`, `tabs_create` and `tabs_create_mcp` follow the browse mode (`CLEARCART_BROWSE_MODE`, above), checked by parsed origin, so `https://shop.example@evil.example/` is refused. Localhost and private network addresses not in `CLEARCART_ALLOWED_ORIGINS` are blocked in any spelling (`[::ffff:127.0.0.1]`, `[::7f00:1]`, `[fec0::]`, `2130706433`), under loopback DNS names (`localtest.me`, `127.0.0.1.nip.io`), and when a name resolves to one (a DNS lookup before opening).
- On the Open Claude in Chrome path, page tools (`computer`, `get_page_text`, `read_page`, `find`, `form_input`, `read_console_messages`, `set_tab_focus`) first check the target tab's current URL with `tabs_context_mcp`, so a page script redirect is caught before Claude reads the page; an unknown tab or URL is denied. Our extension does the same check itself and also checks the IP each page actually came from.
- After every browser call, a PostToolUse sweep sends any agent tab on a blocked site (a clicked link, a redirect) back a page, or to a blank page, and tells Claude. It fails closed: if the sweep cannot run or a tab will not move, Claude is told and every browser call is refused until a sweep succeeds.
- `server.ts` refuses any HTTP request or WebSocket upgrade whose `Host` header is not `localhost`, `127.0.0.1` or `[::1]` with its own port (`hostcheck.ts`), so a DNS rebinding page cannot read `/cartesia-token` or open `/session`.
- While card values are in the form, the guard blocks `computer` (screenshots included), `read_page`, `get_page_text`, `find`, `form_input`, `javascript_tool` and `read_console_messages`.
- A spoken yes is withdrawn when the user says anything more, or Claude takes a browser action, before `pay_with_saved_card` runs (a Danger mode announcement excepted).
- `request_checkout` reads the order back and treats the next `user_text` as the answer. Only an explicit yes ("yes", "yeah", "yep", "confirm", "go ahead", and no "no", "wait" or "change") confirms it. Each confirmation pays once.
- Button lock (see below): clicks, Enter and Space, typed newlines and `form_input` on protected controls are denied, and `navigate` refuses checkout and payment URLs on every site: checkout pages open only through `request_unlock`.
- `pay_with_saved_card` runs only over the Orbi extension. It picks the saved card first (the default, or the one the user named), before the yes is spent. Then it checks the tab and site the yes was given on, that the page is on a site Orbi may use, that the page total and cart still match the yes, and that the page has exactly one card number, expiry and security code (in any frame) and one order button. Only then is the card decrypted, for one `fill_card` call. It presses Place order once through the unlock gate, waits for an order page, emits `receipt` and returns `{ ok, last4, nickname }`, or a short error. The card fields are emptied again unless the page shows none. On the Open Claude in Chrome path it spends the yes and refuses: the user finishes checkout themselves.

## Button lock

Claude's browser tools can never press a protected control (order commits, wallets, subscriptions, saved cards, sign in, the submit of a card or password form, anything inside `data-clearcart-protected`); opt-in boxes are uncheck only. The rules live in `extension/content/protect.js`, shared by both browser paths; the full list is in [`extension/README.md`](../extension/README.md#button-lock).

- **Our extension (`CLEARCART_BROWSER=ext`)**: enforced inside the extension, so no agent-side bug can skip it. See `extension/README.md`.
- **Open Claude in Chrome**: enforced in the PreToolUse hook by `ocic-lock.ts`. `computer` clicks by coordinate are hit-tested in the page. Clicks by ref only are refused with a note to use a coordinate, because OCIC clicks the ref's centre in its own world, which the check cannot see. `key` Enter or Space (and a control character key) and `type` with a newline are checked against the focused element and its form, and `form_input` against the ref (a dropdown never moves onto an opt-in option); any check that cannot run denies the call. Without `chrome.dom` in the main world, a click on a host that may hide a closed shadow root is denied. After `read_page` and `find`, a PostToolUse note names the locked refs and the badges are drawn. The page checks run in the page's main world, so a hostile page could tamper with DOM prototypes to fool them; our extension does not have that gap.
- **Unlock**: only our pay code, through `unlock.ts`. A grant needs a confirmed spoken yes, a page on a site Orbi may use (`origins.ts` `usableSite`: the blocked sites stay blocked) and a page total that matches the yes. It is single use, bound to the tab and origin, and expires after 60 s. The yes itself is pinned too: `request_checkout` records the checkout tab, its site, its priced cart lines and the time, and `pay_with_saved_card` spends the yes synchronously before any await, then refuses one older than 60 s, from another tab or site, or for a changed cart. On the ext path the press also needs a single-use `lock_arm` nonce from the extension, and `press_protected` only presses an order button. `pay_with_saved_card` is the only flow that asks for grants.
- **Prompt**: `prompt.ts` tells Claude what `[locked]` and `[uncheck only]` mean. The prompt is a courtesy; the lock does not depend on it.
